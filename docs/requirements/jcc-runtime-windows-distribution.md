# JCC Runtime Windows Distribution

This document defines the current Windows desktop-entry and installer
requirement. Machine authority is
`data/runtime/jcc/windows-distribution-contract.json`.

## Developer Shortcut

The repository workflow provides one idempotent desktop shortcut named
`JCC Runtime`. It launches without a console window. If the development
Electron application is already running, a repeated click focuses the existing
window instead of starting another Runtime, daemon, watcher, OCR worker, or Host
session. A background process is not launch success: the launcher waits for a
visible application window. If the owning Electron process exists while its
window is still hidden, the launcher asks that owning process to reveal its own
BrowserWindow through a user-scoped local activation pipe. If that channel is
unavailable after the bounded first-window fallback, it invokes Electron's
native second-instance activation path and waits for that owner to expose the
window.

The first window also has a bounded visibility fallback. A stalled
`ready-to-show` event cannot leave JCC Runtime permanently running only in Task
Manager; Electron exposes the window and retries the initial renderer load once.

Install or remove the local shortcut with:

```powershell
npm.cmd run ui:shortcut:install
npm.cmd run ui:shortcut:remove
```

The developer shortcut is only for repository testing. It points to the hidden
repository launcher and requires the local Node/UI dependency installation.

## Release Installer

The public Windows installer must:

- install a signed `JCC Runtime` executable;
- always create a desktop shortcut named `JCC Runtime`;
- create a Start Menu shortcut with the same name;
- use the installed executable and packaged icon as the shortcut target;
- never point a player shortcut at Node, npm, PowerShell, VBScript, a repository
  path, Vite, or any development launcher;
- preserve one application instance, expose a visible window on cold start,
  and focus or recover the existing window on a second launch;
- remove installer-owned shortcuts during uninstall.

Interactive uninstall offers an unchecked data-cleanup component. Without it,
current-user configuration and runtime data are retained. Selecting it removes
only current-user AppData/jcc-runtime-ui and Temp/jcc-runtime-ui. Upgrades and
silent uninstall preserve data. External Provider credentials, emulators,
source repositories and custom Runtime data-directory overrides are excluded.
Cleanup does not follow directory junctions or defer deletion until reboot.
Run `node tools/verify-jcc-uninstall-user-data.mjs` for the seven isolated cases.

`ui/electron-builder.yml` fixes the NSIS shortcut policy, but its presence alone
does not declare the application ready for public distribution. Release remains
blocked until a packaged Windows smoke test proves install, cold-start
visibility, hidden-window second-launch recovery, single-instance focus, clean
exit, uninstall, and shortcut removal on a clean player machine.

## Icon Ownership

The canonical assets are `ui/assets/jcc-runtime.png` and
`ui/assets/jcc-runtime.ico`. They are reproducibly generated by
`tools/build-jcc-runtime-windows-icon.ps1`; do not replace only one format or
hand-edit the binary ICO without updating the generator and verifier.
